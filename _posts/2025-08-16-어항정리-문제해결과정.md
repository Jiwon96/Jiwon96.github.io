# 백준 어항 정리 문제 해결 과정

## 문제 접근 시 잘못된 습관들

### 2차원 배열로 시작한 비효율적 접근
처음 코드를 작성할 때 다음과 같이 불필요하게 복잡한 구조로 시작했습니다:

```python
arr = [ list(map(int, input().split())) for _ in range(1)]
```

이로 인해 코드 전반에서 `arr[0]`으로 계속 접근해야 하는 번거로움이 발생했고, 전체적인 로직이 복잡해졌습니다.

### 좌표계 설정 실수
가장 큰 문제는 **문제에서 제시된 그림과 반대로 좌표계를 설정**한 것이었습니다. 문제 그림에서는 위쪽이 0번째 인덱스여야 하는데, 저는 아래쪽을 0번째로 구현했습니다.

이로 인해:
- `flatten` 함수에서 불필요한 역순 처리가 필요했음
- 회전과 배치 로직이 직관적이지 않았음
- 디버깅할 때 그림과 코드를 매칭하기 어려웠음

### 코드 중복과 임시방편적 해결
동일한 물고기 수 조절 로직을 두 번 구현하면서도 함수로 분리하지 않았습니다. 또한 바닥 정렬 과정에서 "짜치게 코딩한 부분"이라고 주석으로 표현한 것처럼, 예외 처리로 때우는 식의 구현을 했습니다:

```python
if left_width != len(arr[0]): # 짜치게 코딩함... 이거 어떻게 깔끔하게 하지?
    for i in range(left_width, len(arr[0])):
        t_arr.append(arr[0][i])
```

## 정답 코드와의 핵심 차이점

### 데이터 구조 설계 철학
**기존 접근:**
- 처음부터 2차원 배열로 시작
- 복잡한 인덱싱과 예외 처리 필요

**개선된 접근:**
- 1차원 배열로 시작: `arr = list(map(int, input().split()))`
- 필요할 때만 2차원으로 변환
- 작업 완료 후 다시 1차원으로 평탄화

### 좌표계 일관성
**기존:** 문제 그림과 반대 방향으로 구현
**개선:** 문제 그림과 일치하는 직관적인 좌표계 사용

### 함수 분리와 재사용성
**기존:** 
- 물고기 조절 로직 중복 구현
- 복잡한 평탄화 과정

**개선:**
- `adjust()` 함수로 물고기 수 조절 로직 통합
- `flatten()` 함수로 깔끔한 평탄화
- 코드 재사용성과 가독성 향상

## 배운 점과 개선 방향

1. **문제의 시각적 표현과 코드 구조의 일치가 중요합니다.** 그림과 코드가 일치하지 않으면 디버깅이 어려워지고 실수가 발생하기 쉽습니다.

2. **적절한 추상화와 함수 분리가 필요합니다.** 같은 로직이 반복된다면 반드시 함수로 분리해야 합니다.

3. **임시방편보다는 근본적 해결책을 추구해야 합니다.** "짜치게 코딩한 부분"이라고 인식했다면, 그 순간 더 나은 방법을 찾아야 합니다.

4. **데이터 구조 선택의 중요성을 깨달았습니다.** 처음부터 복잡한 구조를 선택하기보다는, 간단하게 시작해서 필요할 때 확장하는 것이 더 효과적입니다.

이번 문제를 통해 코드의 직관성과 설계의 중요성을 다시 한번 깨달았습니다.
