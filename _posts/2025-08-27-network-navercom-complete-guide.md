## 1. 웹 브라우저에서 naver.com 접속 과정

### 🎯 전체 과정 개요
브라우저 주소창에 `naver.com` 입력부터 화면에 웹페이지가 표시되기까지의 8단계 과정

### 📝 단계별 상세 과정

#### **1단계: URL 해석 및 프로토콜 결정**
- **입력**: `naver.com`
- **브라우저 해석**: `https://naver.com` (기본 HTTPS 프로토콜 추가)
- **핵심 키워드**: **URL 파싱**, **프로토콜 결정**, **HTTPS**

#### **2단계: DNS 조회 과정**
```
DNS 조회 순서:
1. 브라우저 캐시 확인
2. 운영체제 캐시 확인  
3. 로컬 DNS 서버 (ISP DNS) 조회
4. 루트 DNS 서버 → .com DNS 서버 → naver.com DNS 서버
```
- **결과**: `naver.com → 223.130.195.200`
- **핵심 키워드**: **DNS 조회**, **도메인 네임 시스템**, **IP 주소 변환**, **DNS 캐시**

#### **3단계: TCP 연결 설정 (3-Way Handshake)**
```
클라이언트(내 PC)     →  [SYN]        → 서버(naver.com)
클라이언트(내 PC)     ←  [SYN+ACK]    ← 서버(naver.com)  
클라이언트(내 PC)     →  [ACK]        → 서버(naver.com)
```
- **핵심 키워드**: **TCP 3-Way Handshake**, **연결 지향**, **신뢰성 보장**

#### **4단계: TLS/SSL 핸드셰이크**
```
1. Client Hello (지원하는 암호화 방식 전송)
2. Server Hello + Certificate (서버 인증서 전송)
3. 암호화 키 교환
4. 암호화 통신 시작
```
- **핵심 키워드**: **TLS 핸드셰이크**, **SSL 인증서**, **암호화**, **보안 통신**

#### **5단계: HTTP 요청 전송**
```HTTP
GET / HTTP/1.1
Host: naver.com
User-Agent: Mozilla/5.0 ...
Accept: text/html,application/xhtml+xml...
Accept-Language: ko-KR,ko;q=0.9
Connection: keep-alive
```
- **핵심 키워드**: **HTTP 요청**, **GET 메소드**, **HTTP 헤더**

#### **6단계: 서버 처리 및 응답**
```HTTP
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 12345
Set-Cookie: ...

<!DOCTYPE html>
<html>...</html>
```
- **핵심 키워드**: **HTTP 응답**, **상태 코드**, **응답 헤더**, **HTML 문서**

#### **7단계: 브라우저 렌더링**
```
HTML 파싱 → DOM 트리 생성
↓
CSS 파싱 → CSSOM 트리 생성  
↓
렌더 트리 생성 → 레이아웃 → 페인트
```
- **핵심 키워드**: **DOM 파싱**, **렌더링 엔진**, **브라우저 렌더링**

#### **8단계: 추가 리소스 로딩**
- HTML에 포함된 이미지, CSS, JavaScript 파일들을 추가로 요청하고 로딩
- **핵심 키워드**: **리소스 로딩**, **병렬 처리**, **브라우저 최적화**

## 2. DNS 테이블과 도메인 이름 변환 시스템

### 🗂️ DNS 테이블의 실체
- DNS는 **전 세계에 분산된 여러 테이블들**로 구성된 거대한 분산 데이터베이스 시스템

### 📊 DNS 레코드 테이블 구조
```
도메인 이름        타입    값(IP 주소)        TTL
naver.com         A      223.130.195.200    300
www.naver.com     CNAME  naver.com          3600
mail.naver.com    A      125.209.222.141    1800
```
- **핵심 키워드**: **DNS 레코드**, **A 레코드**, **CNAME**, **TTL**

### 🌍 계층적 DNS 테이블 구조

#### **루트 DNS 서버 테이블**
```
.com    NS    a.gtld-servers.net
.kr     NS    a.dns.kr  
.org    NS    a0.org.afilias-nst.info
```

#### **COM 권한 DNS 서버 테이블**
```
naver.com     NS    ns1.naver.com
google.com    NS    ns1.google.com
facebook.com  NS    ns1.facebook.com
```

#### **네이버 권한 DNS 서버 테이블**
```
naver.com         A      223.130.195.200
www.naver.com     A      223.130.195.95
mail.naver.com    A      125.209.222.141
cafe.naver.com    CNAME  naver.com
```

### 🔄 DNS 캐싱과 TTL
- **TTL(Time To Live)**: DNS 레코드의 유효 시간
- **캐싱 메커니즘**: 브라우저 → OS → 로컬 DNS → 권한 DNS 서버 순으로 캐시 확인
- **핵심 키워드**: **로컬 DNS 캐시**, **TTL 기반 갱신**, **분산 관리**

## 3. 계층별 프로토콜과 보안 메커니즘

### 🏗️ OSI 7계층과 TCP/IP 4계층 매핑
```
OSI 7계층          TCP/IP 4계층        프로토콜 예시
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
응용계층(7)  ┐
표현계층(6)  ├─── 응용계층        HTTP, HTTPS, DNS, FTP
세션계층(5)  ┘                    SMTP, POP3, IMAP

전송계층(4)  ───── 전송계층        TCP, UDP

네트워크계층(3) ─── 인터넷계층      IP, ICMP, ARP

데이터링크(2) ┐
물리계층(1)   ┘─── 네트워크접근계층  Ethernet, WiFi, PPP
```
- **핵심 키워드**: **OSI 7계층**, **TCP/IP 4계층**, **계층별 캡슐화**

### 🛡️ 계층별 보안 메커니즘

#### **응용계층 보안**
- **HTTPS (HTTP + TLS/SSL)**
  - TLS 핸드셰이크: Client Hello → Server Hello → Certificate → Key Exchange → Finished
  - **핵심 키워드**: **TLS/SSL**, **인증서**, **대칭키 암호화**, **비대칭키 암호화**

- **DNS 보안: DNS over HTTPS (DoH)**
  - 기존 DNS: 평문 전송 (위험)
  - DoH: HTTPS로 암호화된 DNS 쿼리 (안전)

#### **전송계층 보안**
- **TCP 신뢰성**: 시퀀스 번호, ACK 번호, 체크섬, 재전송
- **포트 기반 접근 제어**: 방화벽 규칙으로 포트별 접근 제어
- **핵심 키워드**: **TCP 신뢰성**, **순서 보장**, **오류 복구**

#### **네트워크계층 보안**
- **IPSec**: 인증 헤더(AH), 캡슐화 보안 페이로드(ESP)
- **방화벽과 NAT**: 사설IP ↔ 공인IP 변환 및 접근 제어
- **핵심 키워드**: **IPSec**, **NAT**, **방화벽**, **사설IP vs 공인IP**

#### **데이터링크계층 보안**
- **WiFi 보안**: WEP → WPA → WPA2 → WPA3
- **MAC 주소 필터링**: 허용된 MAC 주소만 접근 허용
- **핵심 키워드**: **WPA3**, **AES 암호화**, **MAC 필터링**

## 4. 패킷 캡슐화 과정

### 📦 캡슐화의 기본 개념
각 계층에서 자신만의 헤더 정보를 추가하여 데이터를 포장하는 과정

### 🔍 naver.com 접속 시 실제 캡슐화 과정

#### **응용계층**: Data/Message (200바이트)
```
GET / HTTP/1.1
Host: naver.com
User-Agent: Mozilla/5.0...
```

#### **전송계층**: Segment (220바이트 = 20바이트 헤더 + 200바이트 데이터)
```
TCP 헤더 정보:
- 출발지 포트: 50234 (랜덤)
- 목적지 포트: 443 (HTTPS)  
- 시퀀스 번호: 1000
- ACK 번호: 500
- 플래그: PSH,ACK
- 윈도우 크기: 65535
- 체크섬: 0x1a2b
```
- **핵심 키워드**: **TCP 헤더**, **포트 번호**, **시퀀스 번호**

#### **네트워크계층**: Packet (240바이트 = 20바이트 헤더 + 220바이트 세그먼트)
```
IP 헤더 정보:
- 버전: IPv4
- 전체 길이: 240바이트
- TTL: 64
- 프로토콜: 6 (TCP)
- 출발지 IP: 192.168.1.100 (내 PC)
- 목적지 IP: 223.130.195.200 (naver)
```
- **핵심 키워드**: **IP 헤더**, **출발지/목적지 IP**, **TTL**

#### **데이터링크계층**: Frame (258바이트 = 14바이트 헤더 + 240바이트 패킷 + 4바이트 트레일러)
```
이더넷 프레임 정보:
- 목적지 MAC: aa:bb:cc:dd:ee:ff (라우터)
- 출발지 MAC: 11:22:33:44:55:66 (내 PC)
- 이더타입: 0x0800 (IPv4)
- FCS: 0x12345678 (오류 검출)
```
- **핵심 키워드**: **이더넷 프레임**, **MAC 주소**, **FCS**

### 🔄 역캡슐화(Decapsulation)
네이버 서버에서는 정반대 과정으로 각 계층의 헤더를 제거하며 데이터 추출
- **핵심 키워드**: **역캡슐화**, **헤더 제거**, **계층별 처리**

### 📏 헤더 오버헤드
```
원본 데이터: 200바이트 (100%)
+ TCP 헤더: 20바이트 (10% 증가)
+ IP 헤더: 20바이트 (10% 증가)  
+ 이더넷: 18바이트 (9% 증가)
━━━━━━━━━━━━━━━━━━━━━━━━━
총 전송: 258바이트 (29% 오버헤드)
```
- **핵심 키워드**: **헤더 오버헤드**, **전송 효율성**

## 🎯 면접 대비 핵심 포인트 요약

### **1. 전체 흐름 이해**
- URL 입력 → DNS 조회 → TCP 연결 → TLS 핸드셰이크 → HTTP 요청/응답 → 렌더링

### **2. 계층별 역할 분담**
- 응용계층(HTTP/DNS) → 전송계층(TCP) → 네트워크계층(IP) → 데이터링크층(Ethernet)

### **3. 보안의 다층 방어**
- 각 계층에서 독립적인 보안 메커니즘 적용
- HTTPS(응용) + TCP 신뢰성(전송) + 방화벽(네트워크) + WiFi 암호화(링크)

### **4. 성능과 효율성**
- DNS 캐싱으로 조회 시간 단축
- TCP Keep-Alive로 연결 재사용
- 패킷 크기와 헤더 오버헤드 고려

### **5. 면접에서 강조할 키워드**
- **계층별 독립성의 중요성**: 각 계층은 독립적으로 동작하면서 서로 협력
- **심층 보안 (Defense in Depth)**: 여러 계층에서 각각 보안 메커니즘 적용
- **성능 vs 보안의 트레이드오프**: 보안이 강할수록 성능 저하, 적절한 균형점 찾기가 중요
